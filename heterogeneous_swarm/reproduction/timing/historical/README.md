# 新P参数的共同状态计时

P采用 kc=0.24、kf=0.16；RAS04采用 alpha=coupling=0.4；MMD19采用 gamma=20。
复用固定的22个历史共同状态：10组初态，以及33001初态下原P0、RAS04、MMD19各在24、86、138、178 s的状态。所有控制器使用相同状态包；本次没有闭环推进或新增轨迹。

每状态每方法预热一次、测量三次；方法顺序随状态轮换。每方法66个测量值；NumPy与SciPy原生OpenBLAS线程数分别核验为1。生效对象中的kc/kf、全部输入与源文件哈希通过核验。

名义计时只包含command调用；认证计时为共同限速后的单个名义候选fresh certify，按该状态任务切向使用共同巡航后备。认证全部返回certified。它不包含局部候选搜索或整步最坏执行耗时。

原目标点生成耗时0.580667 s由未变的target_checks.json复用；当前前三组目标分配耗时分别为1.828900、0.758100、0.586200 ms，均属在线控制前的构造开销。

protocol.json与benchmark_fixed_states.py保留首次预检版本；其因缺少threadpoolctl在任何控制调用前退出，见preflight_attempt_v1.json。protocol_v2.json和benchmark_fixed_states_v2.py仅改用本机BLAS DLL查询线程数，状态、增益、重复次数、调用次序和范围不变；后续一次运行完成。

完整数据：timing_results.json、timing_records.jsonl。状态身份：state_manifest.json、fixed_states.npz。最终复核：checks.json。
